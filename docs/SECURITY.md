# 安全说明与部署迁移指南（CLA-1 加固）

> 本文档是安全加固（CLA-1）的部署与迁移说明。**不承诺绝对安全**：任何联网服务都有残余风险，
> 本文列出的是已知风险与缓解措施，以及**尚未覆盖的范围**（见文末）。发现新问题请提 issue 或 PR。

---

## 1. 访问控制（fail-closed）

### 行为变更

- **未设置访问密码（`mpass` 为空）时，管理后台 `/admin`、全部 `/api/*` 接口、后台网页播放入口
  `/proxy/web.m3u8` 一律 403——本机（127.0.0.1）也打不开**。
  - 原因：本地反向代理可以把公网请求伪装成「回环来源 + 回环 Host + 无 X-Forwarded-For」，
    TCP 来源证明不了原始调用方，「仅限本机」不是可靠的安全边界。
  - 之前的版本：没有密码时任何人可以打开后台、调用全部 API（包括读取/修改配置）。
  - 播放内容（`/interface.m3u` 等订阅入口、`/player` 播放页、`/relay/`、`/proxy/<频道>`）不受影响：
    没设密码时照旧公开，这是本项目的产品行为，**不是**后台安全边界。
- 设了密码后行为不变：`/密码/admin`、`/密码/api/...`。
- 用户访问令牌 `/u/<token>/...` 只能访问内容，从来进不了后台；本次未放宽，也未收紧。
  （空密码时令牌同样进不了后台。）

### 部署建议（按安全性从高到低）

1. **推荐**：对外只暴露 HTTPS 反向代理（如带 TLS 的 nginx/caddy），设置 `mpass`，代理负责证书；
   本服务只监听回环（见第 2 节）。
2. 设置 `mpass` 并把端口映射到局域网。
3. 不设密码：**管理后台/API 整体关闭**，只作纯播放服务使用（compose 默认映射已改为
   `127.0.0.1:1905:1905`）。

### 迁移注意

- **老部署如果一直没设密码**：升级后后台会 403（包括本机）。在 compose 加 `mpass=你的密码`
  （或改数据目录 `system-config.json` 的 `pass`）并重启；重启后入口变为
  `http://ip:1905/你的密码/admin`。
- 升级后启动日志会打印一行黄色提示，说明后台已停用、需要设置密码。

## 2. 端口绑定（compose 默认回环）

- `docker-compose.yml` 的端口映射已从 `"1905:1905"`（绑定所有网卡）改为 `"127.0.0.1:1905:1905"`。
- 要开放给局域网/公网：先设置 `mpass`，再把映射改回 `"1905:1905"`（或更窄的 `"192.168.x.x:1905:1905"`），
  最好放在带 TLS 的反向代理后面。
- 裸 HTTP + 路径密码的固有风险见第 7 节。

## 3. 配置备份默认脱敏

- **后台「导出配置」默认导出脱敏版本**：不含 `users.json`（用户访问令牌）、`extractors.json`
  （模块登录 Token）、`notify-channels.json`（推送机器人凭据），`system-config.json` 里的
  `userId` / `token` / `pass` / `proxy` 字段被剔除。
- 默认还**整份剔除源配置类文件**：`external-sources.json`（订阅 URL 常带签名参数与鉴权头）、
  `my-playlist-config.json` 及全部配置档 `my-playlist-config.<档id>.json`（自定义播放列表地址常带
  签名/Basic 凭据）、`my-playlist-profiles.json`（档注册表）。这些地址里是否藏有凭据无法可靠判定，
  按整份剔除处理，不做「凭据猜谜式」正则脱敏。**脱敏备份导入后这些源不会恢复，需要重新添加
  订阅源与自定义播放列表。**
- 导出时页面会询问：选「确定」才导出**含全部敏感信息（含全部源配置）**的完整备份
  （换机迁移用，自己保管）。
- 旧版导出的完整备份照常能导入；脱敏备份导入后需要重新配置：访问密码、咪咕账号（游客模式可跳过）、
  用户管理、推送渠道、模块登录 Token、订阅源、自定义播放列表。
- 导入前自动快照 `config-pre-import-backup.json` **仍含完整敏感数据**（回滚需要它），保存在数据目录，
  请像保护数据目录本身一样保护它（它不会被打进 Docker 镜像）。

## 4. 出站请求安全（SSRF / DNS 重绑定）

服务器代取第三方内容（订阅列表、HLS 清单/分片/密钥）时，第三方内容不得指挥服务器访问内网/本机/云元数据。

### 生效范围

- **订阅拉取**（`utils/externalSources.js` 默认直连路径）：解析域名**全部** A/AAAA 答案并逐一校验，
  连接使用校验过的固定地址（连接过程不再发 DNS 查询），重定向逐跳重新校验，跨源跳转剥掉凭据头。
- **HLS 清单/分片/密钥**（`utils/hlsProxy.js` 的默认直连路径，含 `/relay/`、`/proxy/`、网页播放入口）：
  同上。
- **自定义源**（`utils/customSourceProxy.js`）：白名单内的目标本机直连（固定地址）。

### 无法固定 DNS 的传输一律拒绝（fail closed）

- **经网络代理出站**（后台「设置 → 网络代理」的「经网络代理转发」、`HTTPS_PROXY` 系统代理、
  模块注入的自定义 fetchImpl）：连接与 DNS 由代理/注入方解析，本机无法保证「校验过什么就连什么」，
  因此在上述受保护路径上**一律明确拒绝**（错误信息会说明原因与出路），既**不静默走代理**、
  也**不静默绕过你的代理设置改直连**。
- **模块自定义回源钩子（fetchProxyMedia / fetchMedia）在公共分发边界 fail closed**：主清单、子清单、
  分片、HEAD、密钥共用的回源边界（`fetchNested` / `pipeUpstream` / `probeUpstream` / 清单直出取回）
  只放行默认守卫直连与「自身每请求都经守卫分发」的受信钩子（当前只有自定义源）；其余未验证的
  模块钩子（redbull/xumo 的 transport.media、深圳台 liveRelay、黑龙江/YouTube 自定义回源等）在生产
  **一律明确拒绝**，不做「假校验后交给不受控回调」。
- 受影响的功能（报错即该功能当前不可用，不丢数据）：
  - 依赖模块注入 fetchImpl / 自定义传输回源的转发播放（YouTube / 海外 / Red Bull TV / Xumo /
    黑龙江 / 四川台 / 深圳台 / TDM 等模块的经服务器转发路径）；
  - 自定义源「经网络代理转发」的订阅拉取与播放转发（其开关仍可取消改直连，见出路）；
  - 部署环境全局设置 `HTTPS_PROXY` 时，HLS 上游直连取流。
- 出路：
  1. 取消「经网络代理转发」开关 → 频道由播放器直连，或（目标在精确白名单内时）服务器固定直连；
  2. 移除部署环境的 `HTTPS_PROXY`（或对该服务配置 `NO_PROXY`）；
  3. 精确白名单 `safeLanAllow` / `msafeLanAllow` 只放行你**明确信任**的主机（连接地址仍是校验+固定）。
- 测试注入（`NODE_ENV=test` **且** `CLA1_TEST_FETCH_INJECTION=1` 同时成立）仅供离线测试放行代理传输
  与未标记钩子；仅设 `CLA1_TEST_FETCH_INJECTION=1` 不生效。生产环境请勿设置。

### 判定规则

- 只允许 `http(s)`；URL 不允许内嵌 `user:pass@`（订阅地址的凭据请用 Basic 认证头，导入时已自动转换）。
- 字面 IP 或局域网主机名（localhost、`.local`、`.lan`、单段主机名等）**只有精确出现在白名单里才放行**。
- 域名解析结果里出现下列任一项即拒绝：私网（10/8、172.16/12、192.168/16…）、回环、链路本地
  （169.254/16，含云元数据 169.254.169.254）、CGNAT（100.64/10）、基准测试段（198.18/15）、
  IPv4 映射 IPv6（`::ffff:0:0/96`，**不论映射出的 IPv4 是否公网，一律拒绝**）、NAT64/6to4 嵌入私网 IPv4、
  Teredo、ULA、链路本地/站点本地/组播/文档段、保留段。
- **空答案与混合答案（一个公网一个私网）整体拒绝**。
- 198.18.0.0/15 被拒绝：使用 fake-ip 透明代理的部署，若订阅拉取因此失败，把目标域名**精确**加进白名单
  （白名单目标会固定连接地址，fake-ip 环境下由代理接管）。

### 局域网访问白名单

需要服务器访问局域网地址（如 NAS 上的订阅 `http://192.168.1.100:8080/x.m3u`）时：

- `system-config.json`：`"safeLanAllow": "192.168.1.100:8080,nas.lan"`，或环境变量
  `msafeLanAllow=192.168.1.100:8080,nas.lan`。
- **只支持精确主机/IP，可带端口；不支持 CIDR、通配符、子网**。IPv6 用方括号（`[::1]:8080`）。
- 非法条目会被忽略并在启动/变更时告警。
- 没有「关闭校验」的全局开关，也不会加。

### 诚实说明（这些路径**没有**完整防护）

- **经网络代理出站**（后台「设置 → 网络代理」、`HTTPS_PROXY`）与**模块注入的 fetchImpl**：
  在受保护路径上已按上文 fail closed（明确拒绝），不构成静默绕过；但**抓取模块自己的普通接口请求**
  （斗鱼/咪咕/YouTube 等取数、取流）仍走各自的出站实现（含代理），其 URL 来自模块内置白名单，不在本策略范围。
- **尚未接入本策略的出站**：
  - 抓取模块的普通接口请求（斗鱼/咪咕/YouTube 等用 node-fetch 的取数、取流、取 EPG）——它们的 URL
    来自模块内置白名单，不是用户输入；
  - Chromium 网页抓取（`browserLauncher`）——浏览器访问的页面地址来自模块配置与用户填写的源地址，
    且 Chromium 以 `--no-sandbox` 运行（见第 6 节），**不把浏览器当安全边界**；
  - EPG 外部源聚合下载（`epgAggregator`）——URL 由管理员在后台配置；
  - 台标下载（`logoCache`）——已有独立的私网拒绝 + 固定 lookup（与本策略同思路，但判定口径略有差异：
    它把 198.18/15 fake-ip 视为可托管）；
  - 更新检查（`updateCheck`）、内置源下发（`builtInSources`）——固定官方地址。
- 若部署在云上，请同时用安全组/防火墙限制出站，作为纵深防御。

## 5. 请求体与响应体上限

- 后台 API 请求体上限 16 MB（按实际字节数计，chunked 无 Content-Length 同样生效），超限回 413 并丢弃
  剩余上传。
- 订阅正文上限 16 MB；HLS 清单/子清单正文上限 4 MB；超限中止读取（不再只信 Content-Length 头）。
- 视频分片是流式转发，不进内存（带宽由系统/代理承担）。

## 6. Docker：非 root 与浏览器沙箱的实话

- 镜像现在以 `node` 用户（uid 1000）运行。用 `-v ./data:/iptv/data` 绑定宿主机目录时先执行
  `chown -R 1000:1000 ./data`（匿名卷无需处理）。**兼容旧路径的 `-v ./data:/migu/data`
  同样要 chown 1000:1000**——两种挂载形态都依赖宿主目录属主为 1000，这一点尚未在真实 Docker
  环境测试过，请在部署环境自行验证一次。
- **关于 Chromium 的实话**：`utils/browserLauncher.js` 一直以 `--no-sandbox` 启动系统 Chromium
  （容器内无法可靠使用其 setuid/userns 沙箱，与本改动无关）。也就是说：**抓取模块的浏览器进程没有
  Chromium 自己的沙箱**，容器只是普通进程隔离，**不是、也不声称是宿主机逃逸防线**。不要拿抓取模块去
  访问不可信的站点（本项目只访问各平台官网与用户自己填的源地址）。
- `.dockerignore` 已排除运行时敏感文件（system-config.json / users.json / extractors.json /
  notify-channels.json / 各播放列表配置 / 数据目录 / 导入快照 / *.corrupt）以及构建残留
  （artifacts/、.claude/、.env*、*.patch / *.diff / evidence 类审查产物）。镜像仍按白名单复制全部代码
  （`COPY --exclude=logo-pack . .` + .dockerignore 黑名单），未改白名单式 COPY 是因为运行期需要仓库内
  大量内容文件（内置台标、内置列表、脚本、资源），不完全的清单会让镜像缺文件且难以验证；
  黑名单覆盖仍有「清单漏写」的残余风险，属已知限制。
- 依赖安装使用 `npm ci --omit=dev --ignore-scripts`（跳过依赖包的生命周期脚本），且要求锁文件存在
  （缺失时构建直接失败，不再降级成无锁的 `npm install`）。
- 升级镜像（`docker compose pull && up -d`）照常；持久化目录权限请按上述 chown 处理一次。

## 7. 路径密码、HTTP 与供应链的已知风险

### URL 路径密码 / 明文 HTTP

- 访问密码放在 URL 路径里（`http://ip:1905/密码/...`）会**明文出现在**：服务器访问日志、浏览器历史、
  反向代理日志、播放器崩溃报告/遥测、Referer 头（页面内资源）等。这是本项目的既有产品形态。
- 明文 HTTP 下，密码与内容都可在同一局域网/链路上被窃听。
- 缓解：仅在内网/可信网络用路径密码；**公网部署务必走带 TLS 的反向代理**，并在代理层剥掉/不记录
  `/密码/` 路径段；TLS 终端在代理上时，请了解「代理与后端之间仍是明文」这点并自行评估。

### 可变的 latest/main 与第三方镜像（供应链）

- compose 默认镜像标签 `akiralereal/iptv:latest` 是**可变标签**：指向的镜像随发版变化。要固定版本，
  请把标签换成具体版本号（如 `:v4.84.0`）或镜像 digest。基础镜像 `node:22-alpine` 已按 digest 锁定。
- 内置订阅与默认自定义订阅来自 GitHub 仓库的 `main` 分支（`raw.githubusercontent.com`），
  失败时回退到**第三方**镜像（ghfast.top、gh-proxy.com、jsDelivr）——镜像方有能力替换内容。
  这些内容只是播放列表（解析为频道名/地址），不执行代码；但频道名会进你的播放列表，地址会被播放器
  或服务器（按其自身策略）访问。可在后台删除这些订阅，或改成自己的固定地址。
- npm 依赖（puppeteer、undici 等）在镜像构建时从 npm registry 安装，构建期执行的是
  `npm ci --omit=dev`（镜像内已含锁文件）。项目未对依赖做完整性审计，升级镜像即接受其中依赖。
- 斗鱼「动态签名」默认关闭（见下），是唯一「执行远程下发脚本」的入口。

## 8. 斗鱼动态签名脚本（默认禁止）

- 斗鱼网页播放的签名算法随官网页面下发（crptext），此前项目在 `node:vm` 里执行这段**远程脚本**。
  **`vm.runInNewContext` 不是安全边界**（历史上多次出现 vm 逃逸 CVE），此前代码注释里「安全」的说法
  已删除。
- 现在**默认禁止**：斗鱼频道列表照常抓取，播放时明确报错「签名已禁用」。
- 需要斗鱼播放：`system-config.json` 加 `"enableDouyuSigner": true` 或环境变量
  `menableDouyuSigner=true`，**自担风险**；建议只在信任斗鱼官网内容、且能接受该风险时开启。

## 9. 存储型 XSS（后台频道名渲染）

- 订阅列表/频道名属于第三方数据，后台此前直接用 `innerHTML` 渲染，恶意频道名可在站长打开后台时
  执行脚本（能调用后台全部 API）。已改为按上下文转义：文本用 `textContent` 或 `escapeHtml`，
  HTML 属性里的 JS 字符串参数用 `escapeInlineJs`（先 JS 转义、后 HTML 转义）。
- 仍请只从可信来源导入订阅；后台的所有输入（含本页面的）仍是同源脚本执行环境。

## 10. 残余风险与测试说明

- **本轮 CLA-1 选定的测试**全部离线运行（本地临时服务 + 注入的解析器/白名单 + 显式测试缝），
  **不代表整个仓库的所有测试**、也不代表线上行为；真实平台行为需在部署环境自行验证。
- 未在此文档覆盖的新增攻击面、以及上述「诚实说明」列出的路径，欢迎补充修复。

## 迁移清单（升级后要做什么）

1. 设 `mpass`（或保持仅本机使用）。
2. 如对外开放端口：确认改的是回环还是全网卡；优先反代 + TLS。
3. 绑定宿主机数据目录的：`chown -R 1000:1000 ./data`。
4. 需要服务器访问局域网订阅/频道地址的：填 `safeLanAllow` / `msafeLanAllow`（精确主机/IP）。
5. 导出备份时按需选择是否包含敏感信息；旧备份导入不受影响。
6. 用斗鱼播放的：显式开启 `enableDouyuSigner` 并知晓风险。
